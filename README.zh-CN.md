# Vela — AI 私人购物 Agent

中文 · [English](./README.md)

Vela 是一个适合作品集展示的多模态购物 Agent 概念项目。用户可以上传一张穿搭照片（非必选），补充场景、预算与风格方向，然后获得一组数量克制、理由清晰的商品推荐，并通过自然语言继续调整结果。

> 这是产品概念项目，不是真实零售平台。项目内置的商品、品牌和价格均为演示数据。

## 为什么做这个项目

大多数购物推荐产品都在提供更多库存、更多结果和更多点击。Vela 探索的是另一种产品假设：**更少但更可解释的推荐，能降低决策疲劳并建立用户信任。**

这个项目集中展示 AI 产品经理常见的核心能力：

- 将图片与文字偏好结合为多模态输入
- 通过场景、预算和风格收集显性约束
- 生成受约束的推荐结果
- 为每项推荐提供可理解的理由
- 支持用户用自然语言继续调整
- 在完整体验和外部 API 成本之间进行 MVP 取舍

## 核心链路

1. 上传一张当前穿搭或灵感照片，也可以跳过。
2. VLM 只理解画面中可见的服装信号，例如配色、廓形、材质与搭配方式。
3. 用户补充使用场景、总预算和期望的风格方向。
4. Agent 在约束条件下生成推荐策略。
5. 商品卡片展示 mock 商品，并给出具体的“为什么适合”说明。
6. 用户可以继续追问，例如“更休闲一点”或“把裤子换掉”。

为了降低不必要的偏见，Prompt 明确禁止从图片推断性别、种族、健康状况、身材类型、吸引力等敏感或不可靠属性。

## 本地运行

环境要求：Node.js 20 及以上版本、npm。

```bash
npm install
npm run dev
```

打开 `http://localhost:3000` 即可体验。

项目默认运行在 **Demo mode**，不需要 API Key，也能完成“图片 → 场景与预算 → 推荐 → 继续追问”的完整链路。

## 接入你自己的 AI API

先复制环境变量示例文件：

```bash
cp .env.example .env.local
```

然后填写：

```env
AI_API_KEY=你的_API_Key
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4.1-mini
```

Vela 使用标准的 `POST /chat/completions` 请求格式，因此可以接入 OpenAI，以及大多数兼容 OpenAI 接口规范、支持图片输入的模型供应商。

- `AI_API_KEY`：你的私密 API Key。`.env.local` 已被 Git 忽略，不会上传到仓库。
- `AI_BASE_URL`：接口根地址，通常以 `/v1` 结尾，不要包含 `/chat/completions`。
- `AI_MODEL`：供应商提供的准确模型 ID；该模型需要支持图片输入和 JSON 输出。

修改 `.env.local` 后需要重启开发服务。

调用成功时，结果页会显示 **Live AI**；如果 API 配置错误、余额不足或服务暂时不可用，Vela 会自动回退到 **Demo fallback**，确保作品集演示不会卡死。

## 项目结构

- Next.js 16 + React 19 + TypeScript
- 图片只在单次会话中处理，不写入项目文件或数据库
- 一个统一的模型适配接口：`src/app/api/agent/route.ts`
- 本地 mock 商品目录：`src/lib/catalog.ts`
- 响应式编辑型视觉界面
- 支持键盘焦点、表单标签和“减少动态效果”系统设置

隐私说明：Vela 本身不会存储用户图片；在 **Live AI** 模式下，图片会发送到用户自行配置的 AI 服务商，因此仍需遵循对应服务商的数据政策。

## 第一版主动删除的能力

- Amazon / RapidAPI 实时商品搜索
- FASHN 虚拟试穿
- 服务端图片存储与删除接口
- 自动 Moodboard、轮询和后台任务
- 多会话聊天历史
- 长期保存的用户画像

这些能力会明显增加 API 成本、部署复杂度和失败点，但不是验证核心产品假设所必需的。等“解释型推荐是否提升决策信心”得到验证后，再将它们作为第二阶段实验更合理。

## 产品假设与指标

核心假设：当推荐数量更少、符合明确约束，并且每件商品都有针对用户场景的解释时，用户更愿意保存和采纳推荐。

- 北极星信号：推荐结果到保存行为的转化率
- 信任指标：“推荐理由有帮助”的评价比例
- 效率指标：从上传到获得首个可用推荐的时间
- 质量护栏：超过用户预算的推荐比例
- 安全护栏：不当推断敏感个人属性的举报数量

## 作品集讲法

一句话版本：

> 我设计了一个多模态私人购物 Agent，将视觉风格信号与用户的显性约束结合，生成数量克制、理由可解释的商品推荐，并支持通过自然语言持续调整。

建议演示顺序：

1. 先说明问题：商品越多，并不代表用户越容易做决定。
2. 提出假设：约束条件与推荐解释可以提升用户信心。
3. 演示“图片 → 场景/预算/风格 → 推荐 → 继续追问”的完整链路。
4. 说明图片隐私和敏感属性推断护栏。
5. 解释为什么第一版主动砍掉实时电商 API 和虚拟试穿。
6. 最后用指标体系和下一阶段实验收尾。

完整的保留 / 删除 / 改名 / 重写清单参见 [PORTFOLIO_NOTES.md](./PORTFOLIO_NOTES.md)。

## 第二阶段可以验证的方向

- 对比 4 个推荐与 12 个推荐对保存率和决策时间的影响
- 在不改变前端产品结构的情况下接入真实商品目录
- 让用户在推荐前确认或修改 VLM 提取的风格信号
- 仅在用户明确同意后保存历史推荐
- 将“推荐商品是否合适”和“推荐理由是否有用”拆成两个评价维度
